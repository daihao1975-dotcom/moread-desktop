# macOS 发布与唯一安装入口

交付完成后，只保留 `/Applications/MoRead.app` 一个可启动的应用副本，且必须为最新正式发布版本。启动、固定到 Dock、文档默认打开方式均指向该路径，不从构建目录或归档目录启动日常版本。

1. 发布前核对候选版本、源码提交、安装包校验和、签名与公证；分别记录 macOS 验证、Windows CI 和 Windows 实机验收，不混用结论。
2. 获得当次公开发布授权，完成公开内容与历史的隐私检查。先通过正式检查，再发布 Release；用官方 API 回读最新版本、标签提交和资产校验和。更新入口应跳到该最新版本。
3. 安装前确认运行实例路径及是否有未保存文档。需要关闭用户正在使用的窗口时先征得同意。旧版压缩为 ZIP 留档；验证压缩包后移除原来的展开副本，不保留带版本号的 `.app` 备份。
4. 将通过验证的最终应用替换到 `/Applications/MoRead.app`。回读版本和构建提交，验证严格签名、公证票据及 Gatekeeper，检查安装包与安装后主程序一致。
5. 先列出本次构建、导出、备份和 Xcode 归档中的应用副本。将需保留的归档压缩并校验后移除展开副本；只删除已确认属于本次任务且不再运行的构建应用，不删除源码、工作树、用户文档或其他项目。
6. 对已移除的副本逐个注销 LaunchServices，仅注册 `/Applications/MoRead.app`。检查 Spotlight 和启动服务记录，只应有一个有效 MoRead 应用入口。不得为此全局重置启动服务或强制重启用户的 Dock、Finder、IDE。
7. 最终分别报告公开发布版本、应用程序安装版本、唯一有效入口和仍未完成的验收项。若有正在使用的副本无法安全清理，明确标为未完成，不宣称“只留一个”。

后续测试产生的 `.app` 是临时产物，验证结束即清理；长期保留的交付包和恢复备份使用 ZIP 或 DMG，避免再次生成重复的应用搜索入口。
